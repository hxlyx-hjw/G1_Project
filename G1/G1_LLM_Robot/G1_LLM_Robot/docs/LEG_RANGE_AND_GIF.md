# 大范围腿部动作设计与聊天GIF导出

## 为什么不能只增大关节角

当前控制为平衡先验 + 视频腿部偏移 + 策略残差。视频腿部权重从0.15增到1，不等于把有效运动范围扩大到原动作：现有代码还将单关节视频偏移限在±0.5rad，腿部策略残差限在±0.12rad。原先验按固定步态训练，无法保证适应大幅抬腿、跨步、低蹲和快速单腿支撑。模型实际关节范围也不能任意扩大。

更大动作需要：

1. **脚部轨迹与接触时序**：明确支撑脚、摆动脚、落点和足底姿态；视频遮挡时给出不确定度。
2. **根部与重心轨迹**：根据落点安排横向重心转移；现有就地XY参考不能完整表达横向闪身步。
3. **动力学可行性优化**：检查摩擦锥、接触力、力矩/速度限制、支撑变化以及足部滑移。可用接触约束轨迹优化或MPC作为教师。
4. **课程与条件策略**：由可稳定小幅动作逐步扩大，策略最终以足部/根部未来目标为条件；不能仅沿用固定步态先验叠加无限大残差。
5. **质量验收**：完成率、漂移、滑脚、动作误差和扰动测试都达标；奖励高或参考时间走完不等于成功。

## 已实现的第一阶段

`fullbody/curriculum.py` 提供逐级腿部权重课程，已接入后台PPO：

- 从 `leg_weight` 开始，例如0.15；设 `curriculum_target`，例如0.5、1.0或2.0。
- 每次整段评估必须未摔倒、完成参考；阈值可配置。`motion_gain>1` 的高幅度模式默认放宽到最大根部XY误差≤0.20m、最大根速度≤1.15m/s、平均关节MSE≤0.07。
- 连续3次评估达标后权重增加0.05；失败清空连续计数，不强制升阶。
- 升阶时重新初始化采样状态，并重新比较该等级的最佳策略；checkpoint记录它实际使用的腿部权重。渲染与GIF读取权重配置。
- 这是权重课程，不是接触规划或全幅腿部控制器；可能长期停留在某一级，不能承诺达到目标。

向DeepSeek说：

```text
使用 ../vedio_self/test1.mp4 训练，GPU自动选择，初始腿部权重0.15，curriculum_target设为0.5，训练300轮，打开渲染。只在整段评估达标后增加腿部幅度。
```

当前0.15参考对应的误差/速度条件可能不达标，课程会保持原级。这是预期行为，应先改进参考而不是放宽阈值来假装成功。单次确定性片段连续评估不是跨种子鲁棒性证明，后续验收仍需独立扰动测试。

## 聊天GIF工具（已实现并实测）

新增 `robot_export_gif` 和 `robot_gif_status`，总机器人工具17个。导出在独立后台进程完成，不阻塞聊天，显示实际策略物理回放；中途摔倒也会保存片段并报告失败，不生成虚假的运动学成功画面。

聊天示例：

```text
把刚才训练任务的最佳策略导出成GIF，15fps，最多20秒。
查询刚才GIF导出任务的状态。
将 runs/self_test1/training/policy.pt 导出为 outputs/gifs/my_result.gif。
```

工具参数：

- `job_id`：当前聊天任务ID，省略使用最近任务。
- `checkpoint`：可选现有.pt路径，优先于job_id，便于导出历史训练。
- `output`：可选.gif输出路径，默认 `outputs/gifs/gif_<id>.gif`；拒绝覆盖已有文件。
- `fps`：1~30，默认15。
- `max_seconds`：最多60，默认30。

启动返回 `export_id`，查询状态返回queued/rendering/completed/failed。完成返回本地GIF路径、帧数、实际仿真时长、是否摔倒、参考是否完成、关节RMSE和最大漂移；同名 `.report.json` 记录指标。截取短片时 `reference_completed=false` 是正常结果。

独立CLI：

```powershell
python -m fullbody.gif_export runs/self_test1/training/policy.pt outputs/gifs/result.gif --fps 15 --max-seconds 20
```

文件写入本地，聊天返回路径；本项目不是Chatbox附件服务，不会自动上传为消息附件。可在聊天回复中提供本地文件路径供打开。

## 验证

真实通过工具分发导出1秒物理回放：10fps、11帧、未摔倒，输出及指标已生成。课程升阶与漂移阻止升阶有自动测试。课程机制已集成并完成短训练验证，但尚未通过长期训练证明能够稳定达到更大腿部幅度。
