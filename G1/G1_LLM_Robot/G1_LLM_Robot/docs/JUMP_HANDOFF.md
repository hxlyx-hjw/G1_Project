# 跳跃窗口保持与行走交接

跳跃成功后窗口不再自动关闭。它保留稳定落地的快照，供观察；状态文件和 `handoff.npz` 在窗口关闭前就已生成，聊天不需要等待窗口进程退出。

聊天示例：

```text
使用协调网络跳跃一次，保持窗口；稳定后从落地点向前走0.5秒。
```

流程：

1. 跳跃从当前行走会话的XY和朝向开始，采用保守站姿初始化，不延续尚未停止的行走动作；当前动作未完成或已摔倒时拒绝启动。
2. 完成腾空、落地并保持1.5秒未倒后，保存根部位姿、根部速度、29关节状态及腿部平衡策略缓存。
3. `robot_coordination_status` 查询到稳定结果时自动导入当前RobotSession。也可显式调用 `robot_jump_handoff(task_id)`；后续walk/goto/turn/sequence/arm/waist/stop执行前同样检查交接。
4. 按关节名称映射至现有行走模型，同步目标、策略相位和仿真时间；保持原世界位置，不复位到原点。交接后空闲暂停，后续指令才继续推进。
5. 跳跃窗口继续显示落地快照；后续动作显示在原行走窗口。可手动关闭跳跃窗口，或调用 `robot_jump_close_window(task_id)`。关闭窗口不重置行走状态。

跳跃尚未完成时后续动作不会在旧位置执行，会返回等待提示；失败时拒绝导入。重复交接同一任务不会再次覆盖当前行走状态。CLI默认 `--viewer` 保持窗口，可用 `--no-hold`恢复运行后退出。

真实GUI链路验证：`python -m examples.jump_handoff_smoke`。已验证窗口持续打开、落地状态导入、随后前进0.5秒未摔倒，测试最后显式关闭窗口。全套36项测试通过。

注意：交接成功仅在目前同一G1关节结构与保守小跳中验证，不代表任意落地或实机状态可直接迁移。跳跃开始仅继承位置和朝向，落地时才导入完整物理状态。
