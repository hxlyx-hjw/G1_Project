# 跳跃与关键节点—质心协调网络

## 已实现和验证

新增独立 `coordination/` 包。保留原有Start、行走策略、视频训练、节点/空间技能库的接口和控制状态；跳跃运行于独立模型和进程，不在当前行走会话中瞬间接管。

使用全29自由度力矩模型，仅通过关节电机施力；根部没有外力、瞬移或强制固定。状态机覆盖站立、下蹲、蹬伸、腾空、落地；落地后切换已有腿部平衡策略恢复。成功标准为连续无足部接触≥0.04秒、真实再次接触、落地后保持≥1.5秒且未触发摔倒阈值。

当前保守小跳实测：

| 条件 | 结果 |
|---|---|
| 无协调网络 | 失稳，未完成落地保持 |
| 有协调网络 | 连续腾空0.130秒，落地后保持1.5秒，未摔倒 |
| 起跳时刻 | 约1.202秒 |
| 落地时刻 | 约1.332秒 |
| 相对站立质心最高上升 | 约0.0184米 |
| 最终骨盆高度 | 约0.768米 |

这是单一初态/模型下的小跳，不是大跳、远跳或多初态抗扰能力证明。更深下蹲和较大腾空测试仍可能落地失败；不得将降低跌倒阈值当作改善。

## 网络结构

`CoordinatorNet`是以真实质量加权全身质心为中心的星形图网络：

- 14个核心节点：骨盆、躯干、左右肩/肘/腕/髋/膝/踝。
- 每节点输入相对质心的位置3维、速度3维。
- 中心输入：质心相对双足中心的XY误差、质心XY速度、根部两个角速度。
- 共享节点编码器提取48维表示，汇聚后与质心特征连接，输出29个关节的修正角，限制在±0.08rad。

质心通过MuJoCo `subtree_com`按模型质量计算，教师用质心Jacobian求解受限纠偏。网络以教师回归训练，不是端到端强化学习。质心投影控制近似使用双脚中心，不是完整支撑多边形、接触力优化或飞行姿态控制。腾空时禁用该支撑纠偏。

CUDA实训：2500个随机姿态/速度样本，80%训练、20%留出，120轮，留出MSE约2.13e-5 rad²。该误差仅说明拟合教师，不代表物理平衡提升；上述物理对照才是当前有限证据。

## 运行

项目根目录执行：

```powershell
# 自动选择GPU训练协调网络
python -m coordination train

# 使用协调网络独立小跳，打开3D并保存GIF
python -m coordination jump --viewer --gif --output runs/jump/manual

# 无网络对照，预计当前参数失稳
python -m coordination jump --no-coordinator --output runs/jump/baseline
```

网络权重：`runs/coordination/com_graph.pt`。跳跃报告和轨迹：输出目录中的 `report.json`、`trajectory.json`；加 `--gif` 后生成 `jump.gif`。跳跃未达到成功条件返回退出码2。

`strength`仅在0.5~1.3内控制蹬伸阶段刚度比例，不能承诺指定跳高。调参集中在 `coordination/config.py`。

## DeepSeek聊天

启动 `python Start.py --mode chat`，可以说：

```text
训练关键节点与质心协调网络，自动使用GPU。
在独立仿真里使用协调网络进行一次保守小跳，打开窗口并录制GIF，告诉我是否稳定落地。
查询刚才协调任务的状态。
```

新增 `robot_coordination_start(operation=train/jump, viewer?, record?, device?)` 和 `robot_coordination_status(task_id)`。工具立即返回task_id，不阻塞聊天；跳跃不会让当前RobotSession的位置改变。任务完成后渲染窗口随独立跳跃进程关闭，GIF和报告保留。协调任务目前不接入训练取消工具，不会自动登记为技能库的合格策略。

现有DeepSeek `--list-tools`若使用静态旧清单，应以RobotToolkit.schemas()为实际注册集。

## 范围与后续

- 32项离线测试通过，涵盖网络形状与修正限幅、真实质心Jacobian特征、小跳落地、原有系统回归。
- 现有视频训练、技能回放不默认启用新网络，避免改变历史checkpoint的控制语义。
- 未来接管步行/视频模仿需加入协调网络版本、控制参数和重新评估；当前仅提供独立协调网络和小跳能力。
- 当前全身训练模型除足部外禁用了网格碰撞，不能检验完整自碰撞和身体跌倒接触，不可部署实机。
